# Runtime, UI and Android

## Connection ownership and security

LAN and remote access have separate lifecycles and pairing authorization. Android unifies saved computers in its device list; it does not make the underlying authorizations interchangeable. Read `src/access.ts`, `src/gateway.ts`, `src/remote.ts` and the selected provider/controller before changing state transitions.

Use generation and ownership checks for asynchronous start/stop, provider switching, component download, retries and late process exits. An old callback must not stop a newer tunnel, overwrite its Origin or update a disposed UI. Reconcile prior effects after cancellation; retrying is not rollback.

A terminal controller failure must invalidate its queued events before awaiting resource cleanup. Deduplicating failure reports alone still permits a queued login or ready event to revive a failed connection. Preserve the first actionable failure and its validated setup URL, await actual resource termination, and keep cleanup failures visible and retryable. [Funnel lifecycle tests](../../../../tests/funnel-lifecycle.test.ts) cover error/close ordering, late protocol events and explicit recovery.

For persisted provider switches, a failed state write must leave a confirmed running state and permit a retry. Exercise the actual controller and disk failure together, including reconnect/reset, rather than checking only the settings store. [Provider persistence tests](../../../../tests/remote-persistence.test.ts) own the durable-before-transition behavior. A main Caddyfile containing a default site or an old management comment can also contain user sites; require whole-file evidence before replacing it. [VPS preservation tests](../../../../tests/vps-caddy-preservation.test.ts) execute the generated shell against owned files.

Preserve precise Origin checks, HTTPS trust, LAN/private CA pinning, device token handling, CSRF and targeted revocation. Never fix a connection by ignoring certificate errors globally, sending credentials to a discovered arbitrary address, exposing the DSH loopback port publicly or weakening third-party WS policy.

Missing Origin and Fetch Metadata are not affirmative same-origin evidence. For browser management writes, inspect the actual DSH route and CORS/OPTIONS behavior before changing admission. The [local admin guard](../../../../src/http-security.ts) accepts a precise non-simple Web JSON marker only under its existing local-peer/Host restrictions; Desktop retains separate authentication. Keep management preflights denied and follow the [reverse-proxy restriction](../../../../SECURITY.md#listeners-and-desktop-administration). Verify foreign simple requests, preflights and redirects with actual browser request/mutation counts, not only a Fetch error or resolved opaque response.

A proxy's direct TCP peer can be shared by every phone. Keep anonymous failure limits separate from valid-secret admission and authenticated-device budgets; never repair shared-budget starvation by trusting arbitrary forwarded-IP headers. Validate cheaply before entering a mutation queue, then recheck expiry/revocation inside it. Pending operations remain accounted for after caller disconnect until the physical work settles. [Authentication admission tests](../../../../tests/auth-rate-limits-gateway.test.ts) cover shared peers, bounded work and device rotation.

Distinguish network unavailability, changed address, expired credentials, authentication failure and computer-side revocation. A timeout is not evidence that the computer removed the device. Verify the active discovery identity before merging a changed cpolar Origin into a saved computer. App credentials stay Keystore-protected; display names and addresses must not expose Tokens.

An absolute state-file path is not a computer identity: independent computers commonly use the same path. Automatically identified entries without a pairing CA use the persisted random installation ID; explicit operator IDs and LAN/self-signed FRP CA fingerprints retain their existing meaning. Copying the entire state also copies that identity. Read [the identity resolver](../../../../src/gateway-identity.ts) and [plugin composition](../../../../src/plugin.ts), not only the config parser's legacy fallback.

Exclusive file creation does not make its subsequent write atomic: another starter can observe the new empty identity file. [Identity publication](../../../../src/installation-id.ts) writes and secures a complete private candidate, then publishes it with an atomic no-replace hard link. Preserve the winning identity and refuse unsupported filesystems rather than replacing it or falling back to a path hash. [The controlled race tests](../../../../tests/installation-id.test.ts) hold candidate writing at a barrier instead of relying on repeated concurrent runs.

Bind a new native identity to its issued credential, not to the latest discovery response. [Device persistence](../../../../src/storage.ts) reads both supported generations and writes the current generation while retaining optional identity bindings. [AccessController](../../../../src/access.ts) keeps legacy records unbound and supplies their legacy response identity; [the Gateway](../../../../src/gateway.ts) projects the authenticated identity without changing native wire fields or overriding a pinned CA. [Storage regressions](../../../../tests/access-storage.test.ts) cover mixed old/new credentials and restart. Never migrate a legacy record by guessing its identity from a new QR code.

An identity fix cannot recover an App credential already overwritten by a collision. Re-pair only affected computers, retain usable old records and let the user remove local duplicates; do not revoke server credentials automatically. Stop the prior Gateway normally before updating and never mix old/new writers on one state directory. A storage-generation upgrade may prevent older plugins from reading it; consult [backup and downgrade precautions](../../../../SECURITY.md#installation-identity-and-device-state-upgrades) instead of resetting data or promising automatic rollback.

Optional downloaded components belong to a private managed directory derived from the user's actual DSH state. Preserve fixed-source/size/hash checks, archive extraction limits and parent-directory ownership. No hidden service installation, PATH edits or startup registration. Cleanup must distinguish plugin-owned components from a user's external proxy or system installation. A bounded Windows filesystem retry must not weaken path checks or destroy the rollback copy.

An MSI administrative install (`msiexec /a`) is not ordinary archive extraction: it can execute installer actions and create protected child ACLs that the calling account cannot read or remove. For portable components, keep extraction in the caller-owned staging directory through read-only database/CAB access, not elevation, ownership takeover or global ACL changes. [The Windows cpolar reader](../../../../src/windows-msi-extract.ts) never starts installer actions; [native fixture checks](../../../../tests/cpolar-readonly-msi.test.ts) and `smoke:cpolar-component` verify the resulting executable and cleanup without running it. Stage-specific errors must retain safe exit/timeout details without raw commands, paths or output.

Read the pinned ZIP through Unicode-aware .NET paths into a single new MSI file, not a general archive destination. Bound entry count, declared and actual copied bytes, reject links/unsafe entry names, and close all streams. CAB extraction uses the Unicode `SetupIterateCabinetW` callback to select one verified member in a fresh directory; reject continuation, duplicate matches, incorrect sizes and callback errors. Windows system tar/expand commands and ANSI path handling differ; native smoke must keep Unicode staging paths rather than substituting ASCII to pass. Fixed PowerShell scripts use environment data and named streams, never the automatic `$input` variable, which can wait for subprocess stdin.

Response bodies and extension streams need cleanup even when rejected before reading or pipeline ownership. Cancel unused Fetch bodies on HTTP, length or redirect rejection and before following a validated redirect; release reader locks after completion or failure. Dispose an extension stream if metadata validation or response-header writing fails before `pipeline()`. Cleanup failure must not replace the original validation error or turn a nonretryable verdict into a transport retry. Observe cancellation, closure and listener release, not only an error response. Reuse the [shared downloader](../../../../src/component-download.ts) and [its tests](../../../../tests/component-download.test.ts), and the [Gateway response handler](../../../../src/gateway.ts) with [HTTP stream regressions](../../../../tests/extension-gateway.test.ts).

Lexical path containment does not prevent an owned ancestor from being a junction or symlink to another directory. Use `src/managed-files.ts` for component/configuration mutation: refuse linked parents, unlink a selected leaf link without traversing it, retain a recoverable replacement backup, and await cleanup before reporting completion. Do not retrofit ACLs on an existing directory that may have unrelated children; secure newly created directories and sensitive temporary files before promotion. `tests/managed-component-files.test.ts` and `tests/caddy-file-lifecycle.test.ts` cover these paths.

Certificate reuse requires a matching private key as well as a trusted certificate. Stage both files and retain recovery copies until both promotions succeed; a single-file atomic write is not a certificate/key transaction. Repair a leaf under its pinned CA instead of replacing the identity. [Certificate publication tests](../../../../tests/managed-certificate-publication.test.ts) and [FRP identity tests](../../../../tests/frp-ingress-identity.test.ts) cover interrupted promotion and key mismatch.

Managed Caddy build/review/distribution and runtime installation are separate states. Consult `docs/CADDY_MANAGED.md` and its English counterpart; a successful build or release does not enable an unpinned production catalog, prove certificate renewal or authorize component publication.

## Connectivity and remote performance

Check the chain that matters: actual computer process → local gateway → public Origin → static boot resources → authenticated API → WebSocket Workspace reads. A health response, TLS handshake or screenshot of a login page is not full remote acceptance. If the same public URL is slow on the computer, separate provider/network limits from App rendering.

Diagnostics must identify the measured side and failed stage, not turn computer egress into phone acceptance or a public outage. System DNS can select a tailnet-only route that a Funnel-only listener does not accept; shared-address/tailnet ranges are not Fake-IP. Preserve TLS/HTTP failures rather than hiding them behind a DNS hypothesis, and do not silently add public DNS or change system settings. [The diagnostic guide](../../../../docs/CONNECTION_DIAGNOSTICS.en.md), [context classifier](../../../../src/diagnostic-network-context.ts) and [path regressions](../../../../tests/diagnostics-paths.test.ts) own the current behavior.

Check runtime index-injection signatures, not only a local DSH source copy: Peer-aware collectors require the authenticated request's Peer from public admission. Do not invoke them without that context, fabricate a Peer or swallow admission rejection. Optional script-inspection failure should remain visibly unverified without hiding other diagnostics; [the plugin route](../../../../src/plugin.ts) and [its tests](../../../../tests/plugin.test.ts) cover this compatibility path.

Independent pnpm profile paths can still share hardlinked package files. Installing another profile can change an existing file's `ctime` without changing its bytes; DSH's metadata-based HMR revision can then change during mobile boot. The owned profiles in `scripts/mobile-boot-fixture.mjs` use `packageImportMethod: copy` to isolate file metadata. `scripts/probe-pnpm-client-metadata.mjs` retains an explicit `auto` control and records actual dev/inode/link counts, file hashes and live registry revisions; separate path strings alone are not isolation evidence.

An iframe document also requests `Accept: text/html`; that header alone does not identify the DSH shell. Keep Mobile boot rewriting aligned with DSH's actual frontend entry points and boot manifest, and forward community preview/error documents to their original route without replacing them with the homepage. Include the browser's iframe headers, response body and upstream target in `tests/gateway.test.ts`; framing-policy headers alone do not establish that the preview was served.

An upstream auth plugin can classify HTML Accept as browser navigation and return a successful bounce document rather than the expected cookie-exchange redirect. Mark the Gateway's internal exchange as non-navigation, while preserving the configured upstream Origin, redirect-status and Cookie validation. Do not accept arbitrary HTML 200 responses, follow redirects or forward the upstream Cookie to a phone. [The pinned community-auth smoke](../../../../scripts/smoke-upstream-auth.mjs) distinguishes real navigation and exchange responses before checking authenticated boot and Workspace traffic.

For cellular/public-route tests, use the phone's real network. Mark USB reverse, loopback routing, local reverse proxies and simulated TLS as isolated evidence. If temporarily switching providers is authorized, record and restore the selected provider; do not silently abandon a working tunnel.

For LAN failures, distinguish wrong interface/address, listener binding, firewall policy and network isolation with checks from both ends. Sharing a Wi-Fi name does not guarantee routing between clients or campus subnets. The plugin cannot bypass a router's client isolation; do not prescribe globally disabling the firewall or exposing all interfaces as a universal fix. Use the existing diagnostics and an appropriate remote route when the network cannot provide LAN reachability.

Changing an existing LAN binding is not first-time setup. Preserve its CA/key paths, extra trusted networks, paired credentials and durable enabled preference; do not recreate firewall rules or call the setup initializer to move an interface. Serialize configuration and enable/disable writes, drain admitted work before teardown, and distinguish confirmed recovery from an unknown/failed recovery. The [rebind owner](../../../../src/lan-rebind.ts), [controller](../../../../src/control.ts) and [HTTP regressions](../../../../tests/plugin.test.ts) cover repeated changes and unreadable configuration; a second successful call to the initializer does not test this lifecycle.

For self-hosted FRP or a reverse proxy, follow the owning provider guide: the local remote Gateway and the public HTTPS terminator have different responsibilities. FRP HTTPS forwarding does not itself terminate TLS for an HTTP backend. Preserve the single-purpose mobile Gateway rather than adding an unrestricted TCP/UDP proxy. Approved custom HTTPS Origins are valid remote addresses; do not recognize remote connections only by a cpolar or Tailscale hostname suffix.

Check the IP family of each proxy hop independently: a phone can reach the HTTPS terminator over IPv6 while that proxy connects to an IPv4 Gateway. The source CIDR authorizes the latter direct socket peer. Test both frontend-IPv6/backend-IPv4 and backend-IPv6 paths before attributing a 403 to the phone's address family; forwarded client headers cannot establish the backend peer.

Preserve revision-aware asset caching, compression and bounded history pagination. Do not replay API writes or model operations while retrying transient static requests. Long API operations must not be cut off by an ordinary static-transport timeout. Automatic recovery should renew trust and restore transport while retaining the existing WebView/document when possible, not repeatedly reload the homepage and discard draft/scroll/menu state.

An optimistic message bubble and cleared draft can appear before a prompt request or Host acknowledgement. Trace the actual published DSH send consumer, request and acknowledgement before diagnosing lost delivery; a module-update SSE is not the conversation stream. Keep transport rejection, Host acceptance and model execution distinct, and never add automatic write replay from a screenshot or access-log gap alone.

An authenticated event stream can remain silent beyond the ordinary transport budget. Verify actual event-frame delivery after that budget, not only open sockets or HTTP 200; Gateway compression can buffer sparse frames. Retain connect/header deadlines and credential/cancellation ownership when granting a known stream its long-response policy. Read [the event-stream regressions](../../../../tests/gateway-event-stream.test.ts) and the actual DSH consumer: a caught fetch-reader error may stop module updates without emitting a browser `pageerror` or triggering whole-page reload.

Rewriting an initial boot graph also owns its later graph updates. Raw upstream HMR can unload the Mobile layout or restore excluded modules once buffering is removed. Use the same graph projection for HTML and the document's event stream, freeze the page's module choices until its next load, and keep stock/legacy requests distinct; a page-view marker is not authentication. Reject invalid views or event responses without forwarding raw graph data. [The bounded stream transform](../../../../src/mobile-graph-events.ts) owns framing and late-output rejection; its caller must cancel and drain external projection work. Require a real packed browser to remain mounted after its first event graph, then receive a later rebuild without losing the document or draft.

Treat boot batching targets separately from security limits. A smaller target batch or fewer stored merged plans must not reject a previously accepted module graph that remains within the safety limits. Where the loader supports it, fall back to validated individual resources while retaining the Mobile layout replacement, exclusions, dependencies and each module exactly once. Test actual byte budgets and complete graph coverage, not only the number of batches; [the budget projection](../../../../src/gateway.ts) and [its HTTP regressions](../../../../tests/mobile-boot-budget.test.ts) own this fallback.

Before adding caching, identify its location and intended benefit: browser transfer reuse, Gateway-to-DSH waiting or repeated computation. A Gateway hit that still sends the full body does not reduce phone-link bytes. Distinguish revisioned static assets, authorization-bound documents and mutable API data; do not share a document or Session identity merely to stabilize validators. A cache side path must preserve normal forwarding backpressure and bound bodies, key/header metadata and entry count. Being disabled by default does not remove these obligations. Follow [the caching guide](../../../../docs/SLOW_CONNECTIONS.en.md#static-resource-caching-and-repeated-downloads) and retain the [Gateway](../../../../src/gateway.ts)'s authenticated streaming behavior.

Entity tags use HTTP quoted syntax and conditional GET/HEAD weak comparison, including lists and `*`. Authenticate and check the resource before returning 304. When gzip changes representation bytes, do not retain an identity strong tag, length or range metadata; preserve correct encoding negotiation on both 200 and 304. Missing upstream validators do not justify inventing a content hash from an arbitrary URL or buffering an unbounded body.

For Windows permission failures, preserve ACL-before-use and expose only the operation stage, wait duration and safe machine fields. Cordis renders Error causes recursively; retaining a raw subprocess cause can reveal SID arguments, private paths or command output despite a redacted outer message. Diagnostic improvements are not evidence that startup contention or a loader dependency delay is fixed.

Attach error handling to both WebSocket peers. Reserved close codes such as 1005, 1006 and 1015 describe local conditions and must not be transmitted as close frames. Test invalid peer input and teardown without allowing an unhandled socket error to terminate DSH. Third-party terminal/realtime routes require exact-path approval; do not replace that with an unrestricted WS proxy.

## Mobile presentation

Missing APIs and unsupported JavaScript syntax require different handling. Inspect the actual published frontend: an API shim cannot repair a parser failure in DSH's bundle. Keep the early diagnostic script parseable on its intended old engine without claiming that engine can run the application. Fixed error categories avoid reflecting sensitive messages/URLs; preserve CSP nonces through the DOM nonce property, leave mounted DSH and its loader alone, and offer explicit recovery without automatic reload. [Boot-feedback smoke](../../../../scripts/smoke-mobile-boot-feedback.mjs) checks these controls, not a physical old WebView or Android Activity.

Reuse DSH's existing frontend semantics and theme tokens. Keep plugin-owned selectors narrow, preserve desktop behavior and support light/dark modes. The Android top native toolbar stays hidden; computer switching belongs in the DSH web page's General settings, not in the native device-list settings where it is redundant.

Inspect parent layout, viewport ownership and the actual consumer before changing CSS. Conversation components must not change the detection of the entire mobile page. Optional module selection is a whole-module loading choice with required/dependency checks; it cannot hide every arbitrary toolbar component or fix arbitrary community-plugin layouts.

A populated view can contain valid text while its virtualized ledger and scrollport have zero height. Compare the same owned Session with the optional skin loaded and omitted; inspect the clipping ancestors and matched root-layout rules before blaming missing data. Protect only plugin-owned geometry when a broad foreign rule overrides it; do not recreate private stock classes or reset the skin's palette. [The layout ownership smoke](../../../../scripts/smoke-mobile-layout-ownership.mjs) retains a controlled collapse case and observes actual scrolling and hit targets. The raw `frontend=stock` diagnostic route bypasses mobile boot rewriting and module selection, not necessarily installed client adaptation or custom assets; it is neither a plugin-free control nor a ready-made device layout setting.

A visible row can still be clipped or lose hit testing to an ancestor's pseudo-element. Compare actual hit targets and clipping ancestors before attributing the failure to grid sizing. Short drawers need both a usable Workspace scrollport and a way to reach larger panel/footer seats; do not fix the list by moving required footer actions off-screen. Scope pointer-event changes to owned content columns and preserve the stock shell overlay's non-interactive container and interactive descendants, rather than enabling every frame child. The packed sidebar smoke exercises the real Workspace consumer and additive slots.

Custom files and extension APIs belong to an authenticated Mobile Gateway page, not every public DSH hostname or phone-sized preview. Keep entry ownership separate from desktop/admin presentation and from server authorization. A Gateway document marker identifies the resource owner but does not authenticate requests. File presence is not client activation: inspect actual manifest/CSS/script requests and applied content, retain safe deduplicated failure notices, and fence late failures before clearing newer resources. [The customization installer tests](../../../../tests/mobile-custom-assets.test.ts) cover ownership, recovery and existing resource budgets; do not relax authentication or transfer credentials to another entry to make customization load.

Measure portrait/landscape, small CSS viewports, larger text, keyboard shown/hidden, drawers, model menus, settings, dock entries, Stop/Send and scrolling. Check touch targets and hit testing after generic settings rules apply. A declared 48px size can still be shrunk by flexbox or overridden by a broader selector.

Keep mobile typography local to the current Origin instead of writing Host settings unintentionally. Whole-page App zoom is a separate preference. Verify paragraphs, code blocks and their real styles after adjustment/reset; a terminal canvas requires its own supported consumer. Public input variables being present do not establish theme support: [typography capability checks](../../../../src/mobile-font-capabilities.ts) observe actual public-token consumers, retain unsupported saved values and avoid a version allowlist. Theme observation stays on owned style/attribute surfaces, not every streaming conversation DOM change. Show an App-only control only when the native bridge advertises the required actions.

Preserve DSH's composition, menu selection, modifiers and send handling when changing Enter behavior. Browser events cannot reliably distinguish every soft and external keyboard; use the existing policy and native evidence rather than a UA guess. Switching sessions should not focus the composer and summon the keyboard. Reuse native DSH file upload instead of adding a duplicate chooser; camera actions remain explicit user actions.

File selection, webpage delivery and Host persistence are different observations. DSH keeps image previews and Files in the browser draft before submission; Host object counts or mtimes cannot establish selection failure. Programmatic drops must supply the actual consumer's file items as well as files, and dragover acceptance is not an attachment acknowledgement. Constructed native transfers can ignore `effectAllowed` and `dropEffect` assignments even when file items work; verify the control properties used by preflight rather than only constructor availability. [The attachment smoke](../../../../scripts/smoke-mobile-attachments.mjs) reads real draft attachment identities and decoded previews without sending a prompt. Browser focus or visibility restoration does not establish cancellation; [the shared chooser](../../../../src/browser-file-picker.ts) settles on selection, explicit cancellation, abort or deadline and preserves late valid results. Omit `capture` for ordinary file selection instead of assigning an empty reflected attribute.

Async settings/forms need disposed-view and stale-result checks. A saved preference must actually affect rendering, and a failed operation should retain the last confirmed value with a short localized retry path. Do not capture microphone audio automatically or call speech recognition verified without a physical recording/recognition test.

Distinguish CSP media-source rejection, unsupported codecs and autoplay denial before changing native media policy. Use a valid clip and observe the actual violation directive, decoded dimensions, playback progress and user activation; arbitrary invalid video bytes cannot establish playback. The [media smoke](../../../../scripts/smoke-blob-media.mjs) checks same-origin/Blob playback and external-source rejection. Its desktop browser result is not physical WebView or arbitrary community-plugin acceptance; retain a user-initiated playback fallback and do not disable Android's general gesture policy to repair a CSP rejection.

Module directories are frontend loading choices, not Host plugin installation or authorization. Group required entries before package namespaces, preserve hidden draft choices, and show stale exclusions that no longer exist or became required. Repair only after an explicit user action; do not silently drop them or weaken server dependency checks. Read/write timeouts leave write completion uncertain, so rereading and retrying are explicit. [The module-settings smoke](../../../../scripts/smoke-client-module-settings.mjs) uses an actual optional skin and owned failure injection. Native settings responses must also match the current bridge and mounted row; [the action controller](../../../../src/mobile-native-settings-action.ts) and its deferred tests cover stale probes, replies and duplicate taps without replaying native navigation.

For local extension Workers, read `docs/EXTENSION_WORKERS.en.md` and the owning protocol/runtime tests. Keep caller settlement separate from execution completion and confirmed exit. Stream cancellation survives header delivery; unread EOF bytes retain budget, and Node flowing `push()` can deliver data without an explicit `read()`. Verify the real HTTP pipeline, fair aggregate progress and explicit recovery without replay. Inherited Node heap flags can override reported Worker limits; inspect the actual launch/guard rather than treating `worker.resourceLimits` as effective-memory evidence.

Verify configured time budgets through the public extension loader and recovery path: an outer fixed timer can override a correct Worker timer. [Worker service tests](../../../../tests/extension-worker.test.ts) check this complete call chain. Notification tags must derive from complete opaque IDs, without truncating or normalizing identities before their bounded digest; [notification tests](../../../../tests/task-notify.test.ts) cover long shared prefixes, Unicode and preserved turn numbers.

Wait for resolved network state in browser fixtures, not a returned Promise's truthiness. Use a bounded asynchronous poll that checks the actual result, as in `scripts/smoke-extension-workers.mjs`; a completed `waitForFunction` call alone does not establish an asynchronous predicate became true. Keep source-content generation separate from runtime instance identity when checking recovery.

## Android and ADB

Read `apps/mobile/README.md`, its Chinese counterpart, the manifest, `MainActivity.kt`, `NativeBridge.kt`, `WindowInsets.kt` and the affected policy tests. Before operating a device, identify the selected serial, package, versionCode, signer, WebView provider and current screen. A different connected device is not interchangeable evidence.

Preserve application identity, Keystore data and existing pairings. A matching-signer upgrade may use an in-place install; an official/debug signer mismatch is not a reason to uninstall or clear data. Use a separately authorized test package when needed. Do not grant unrelated permissions, bypass a lock screen or expose WebView debugging on public interfaces. `MainActivity.kt` enables CDP only for `BuildConfig.DEBUG`; absence of a debug socket on a formal App is not a connection failure or permission to replace its signer. Debug CDP forwards stay on loopback and are removed afterward.

An authentic saved CA expiring is a connection state, not encrypted database corruption. Keep its record readable for removal or re-pairing while the TLS consumer rejects expiry; do not discard other computers or silently replace their credentials. Button, IME and scanned-link submissions share one pairing owner until the result is saved or explicitly cancelled. Device-list refresh must retain slow current results, deduplicate queued/in-flight work, and leave capacity for an explicit connection; a stopped network operation retains its physical slot until exit. Read [PairingAttemptGate](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/PairingAttemptGate.kt), [DeviceStatusPoller](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/DeviceStatusPoller.kt) and their JVM tests when changing these paths.

Native-safe margins own system bars, cutouts and keyboard occupancy per edge. Use the maximum overlapping inset, not summed navigation plus IME, and consume margins already handled by native layout so CSS does not add them again. Keep status/navigation backgrounds and icon contrast aligned with the page. A system resource overlay on an OEM device may change a mode value without exposing a real three-button bar; inspect the actual Insets/screen before claiming that test.

Retain the WebView across supported rotation/window/keyboard changes. Test actual document/editor identity, an unsent draft, scroll/menu state, reference chips and images as applicable. Do not infer preservation merely from saved Origin. Record platform-required Activity recreation or render-process loss separately.

A staged WebView adopted without reloading needs its exact-Origin native message listener registered before the first navigation: AndroidX injects the object only into later navigations. Registering it after the target loads leaves the live document without native capabilities. Keep the staged Bridge inactive until the browser/Origin becomes current, reuse that instance during adoption, initialize document-dependent preferences, and dispose it on abort. Read [NativeBridge](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/NativeBridge.kt), [staged-transfer wiring tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/PlainTextDraftTransferWiringTest.kt) and the [AndroidX API](https://developer.android.com/reference/androidx/webkit/WebViewCompat#addWebMessageListener(android.webkit.WebView,java.lang.String,java.util.Set,androidx.webkit.WebViewCompat.WebMessageListener)). Source-wiring checks are not physical WebView injection evidence.

Opening manual connection or pairing configuration withdraws the previous automatic recovery owner. Removing a queued timer alone does not invalidate an in-flight renewal or cookie callback; fence both results and retry identities before rendering the form. [RestoreAttemptGate](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/RestoreAttemptGate.kt) and [its tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/RestoreAttemptGateTest.kt) own the native generation checks. JVM callback tests and Activity source-wiring checks are not physical-device navigation acceptance.

Restore generations reject late callbacks, not physical concurrency. Keep one logical recovery through Cookie installation and retain a same-credential network slot until its worker exits, including cancelled work and LAN rediscovery. The [restore work gate](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/NativeRestoreWorkGate.kt) coalesces waiting owners without blocking other computers or the UI; its [controlled tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/NativeRestoreWorkGateTest.kt) hold the old worker while testing cancellation, replacement and the overall deadline.

Page-requested renewal uses that same native restore owner, not a second `NativeAuthClient` path. Advertise the capability explicitly, bind it to the active saved credential and document, and cancel by exact request ID. [Client recovery](../../../../src/client-recovery.ts) admits one native attempt per known disconnection; the public Connection's `undefined` state is not evidence of an outage. Dispose subscriptions and timers, withdraw late effects, and await admitted work rather than only clearing the next interval.

Platform Cookie writes need an Application-owned [installer](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/NativeSessionCookieInstaller.kt): Cookie host scope does not distinguish ports, and Activity replacement must not create a competing queue. A queued cancelled batch writes nothing; after platform submission begins, finish the complete Session/CSRF alias group before releasing the host's write slot, suppressing cancelled completion callbacks. Stopping midway can leave a new Session with an old CSRF token even when no successor exists. [Controlled callback tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/NativeSessionCookieInstallerTest.kt) must inspect the final Cookie set, not only write counts; a platform failure is not a successful commit or a rollback.

Every user-waiting connection needs an immediate cancellation action and one overall deadline, including native authentication, queued retries and initial document loading. Ending a request logically does not establish that its network work has exited: withdraw late results first, request transport cancellation and retain its physical execution slot until exit. A transient verdict must still end or update the owned waiting UI; treating it as retryable is insufficient when that caller does not schedule a retry. Cancellation retains existing pairings and does not roll back a one-time pairing already accepted by the computer. Stopping recovery keeps a usable page, not merely an existing WebView object: return a blank/error document to the device list, fencing the asynchronous probe against later navigation or reconnection. Allow retry of a stale unreachable probe and never silently choose another computer. Read [MainActivity](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/MainActivity.kt) and [native cancellation](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/NativeConnectionCancellation.kt) together rather than inferring cancellation from a hidden spinner.

Restore generations identify requests, not the lifetime of a retained WebView. Activity callbacks from an old browser must check the current WebView identity, configured Origin and live Activity before changing UI or scheduling recovery. Do not bind these callbacks to the browser's creation-time restore generation: normal renewal can advance the generation while keeping that browser. Keep TLS rejection and required platform responses intact; ownership guards suppress obsolete Activity side effects, not security handling. [MainActivity](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/MainActivity.kt) and [callback wiring tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/RestoreNavigationWiringTest.kt) own this distinction.

Visible content and completion of every resource are different signals. A validated visible main-document commit releases the full-screen native artwork and animation; do not hide webpage boot progress until components become interactive. Keep a nonblocking cancellation action and the overall deadline until actual visible, hit-testable controls appear, without requiring one layout class or page focus. Keep boot/error and failed-document rejection, bind both stages to the loading attempt and document generation, and stop both loading timers after readiness confirmation. A retained page's controls cannot complete a still-pending native renewal, and a replacement document must not inherit its predecessor's visible state. The branded waiting layer keeps the underlying WebView visible and running; root replacement does not settle its connection owner. [Document state](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/WebViewDocumentState.kt), [WebView client](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/SecureWebViewClient.kt) and [readiness tests](../../../../tests/android-connection-readiness.test.ts) cover these separate states.

Standard WebView file inputs and Bridge `files.pick` are separate paths; the latter's single-file payload limit does not describe the former. Follow [the file chooser policy](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/WebFileChooserPolicy.kt) for platform/MIME selection without broadening filters, adding storage permission or promising a vendor gallery. Bind callbacks to the browser, exact Origin and document, cancel on teardown/navigation, and keep late Activity result codes from consuming a new request. Activity recreation cannot restore a withdrawn Chromium callback; [policy tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/WebFileChooserPolicyTest.kt) and wiring checks do not establish an OEM picker result.

Legacy `onPageStarted` may arrive after renderer navigation commits, too late to settle a file callback owned by the outgoing frame. Where supported, use the navigation listener with an inline executor, invalidate at cross-document start and deny new file requests until every outstanding navigation completes, including non-committing completions. An older completion must not unblock its successor; the late legacy callback must not invalidate a new document's request again. Keep same-document changes separate and feature-detect support rather than rejecting all older providers. [The transition gate](../../../../apps/mobile/android/app/src/main/java/io/github/sayach/dshmobile/WebFileChooserPolicy.kt) and [interleaving tests](../../../../apps/mobile/android/app/src/test/java/io/github/sayach/dshmobile/WebFileChooserTransitionsTest.kt) own these rules. Device acceptance must keep the same WebView and test selection after navigation, reload, cancellation and a held pre-commit response; opening a chooser once is insufficient.

Before each device input, independently confirm that the current foreground window belongs to the selected App or its owned system picker. A previous check in a long command batch can become stale when the user switches apps. Pause input on a different foreground owner; do not inspect or dismiss unrelated content to regain control.

System Back should first dismiss keyboard and webpage layers according to existing DSH Escape/back handling, then perform the agreed App-root behavior. An owned foreground modal must consume Escape before a stock listener closes the settings underneath; closing, keyboard Escape and native-return events share its unsaved-choice decision. Android predictive Back and older callback paths require device evidence; do not test only by dispatching a browser Escape event. Dismissal is claim-based: the page's cancelable native-back event decides whether the App handles it, so a page-level full-screen host that never listens leaves the App to perform its root behavior and close itself. Do not shim arbitrary third-party body-level hosts; document the contract instead ([plugin adaptation guide](../../../../docs/MOBILE_PLUGIN_ADAPTATION.md)).

Use the existing Android unit tests, Debug/release builds and lint for source changes. ADB acceptance should avoid sending model requests, clearing sessions, revealing pairing URLs/Cookies or recording unrelated screen content. Restore temporary zoom, rotation, navigation settings and test drafts; uninstall only an explicitly owned temporary test App when authorized. Leave concise local evidence without publicizing the user's conversations.
