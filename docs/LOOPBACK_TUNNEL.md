# 回环隧道接入（配合自己的 frp stcp）

[English](LOOPBACK_TUNNEL.en.md) · [返回远程访问说明](../README.md#远程访问)

> 插件 0.8.12 起在 **移动访问 → 局域网** 增加 **回环隧道接入** 开关，默认关闭。它不新增远程通道、不安装也不管理 frp，不要求升级 Android App；关闭时行为与之前完全一致。

如果你已经有一台自己的 frps，并希望用 frp 的 **stcp（secret tcp）** 私密代理把 DSH 移动网关带到手机上，可以打开这个开关：网关会把 `127.0.0.1` 与 `::1` 作为额外可接受的地址名，并把这两个名字写进服务器证书。手机访问的其实是**它自己**的 `127.0.0.1:<监听端口>`，由手机上的 frpc visitor 经 frps 转发回电脑上的网关。

需要说准确：插件并不『支持 stcp 协议』。它不读取、不校验、也不管理你的 frp 进程和配置，只做一件事——允许经**本地回环隧道**进来的请求，并让证书覆盖回环地址。通道本身（frps、两端 frpc、`sk`、线路）全部由你自己部署和运维。

> **不要在电脑上直接打开回环链接自测。** 网关本身只监听局域网地址，从不监听 `127.0.0.1`；那个回环地址上监听的是**手机上的 frpc visitor**。在电脑（或任何没有跑 visitor 的设备）上访问 `https://127.0.0.1:<端口>` 有两种结果，都不是功能坏了：
>
> - 端口上没有监听 → 直接连接被拒绝，说明隧道没在跑。
> - 端口上有东西、但 TLS 握手失败（Windows 上常见 `SEC_E_INVALID_TOKEN`，改成 `http://` 则报 `Received HTTP/0.9`）→ 那个监听者是 TLS 服务，但转发目标不对，通常是 frpc 的 `localIP` 指向了网关并不监听的地址。用 `netstat -ano | findstr :3443` 查清是谁在占用该端口。
>
> 要验证隧道是否打通，请在**手机**上访问。

## 适用场景

- 已有自己的 frps（公网 VPS），不想把 DSH 的 HTTPS 端口、域名或公开证书发布到公网。
- 希望用 stcp 的访问控制：只有持有同一 `sk` 的 visitor 才能接入；frp 客户端与服务端之间的连接默认启用 TLS，而 DSH 的 HTTPS 仍由电脑端网关终止，frps 不解析它。
- 手机能运行 frpc（常见做法是 Termux），并接受在手机本地回环地址上访问 DSH。

如果电脑端没有公网入口、也不想自己维护 frps，优先考虑 [iroh 实验性连接](IROH.md) 或其他远程通道。

## 与 iroh 的区别

| | 回环隧道接入 + 自己的 frp stcp | iroh（实验性） |
| --- | --- | --- |
| 谁管理通道 | 你自己部署、配置和维护 frps 与两端 frpc | 插件下载并启动固定版本的 sidecar |
| 手机端如何接入 | 在 Termux 或同类环境里运行 frpc visitor | 完整版 Android App 内置原生传输 |
| 是否需要公网服务器 | 需要，frps 的控制端口要对两端可达 | 不需要 |
| 插件负责什么 | 网关额外接受回环名字、把它们写进证书、提供回环配对链接 | 整条通道、端点证书与配对描述符 |

两种方式都不保证一定连通：线路、防火墙、运营商和你的 frp 配置仍决定实际结果。

## 拓扑

```text
手机 App / 手机浏览器
  └─ HTTPS → 127.0.0.1:3443（手机上的 frpc visitor 监听）
       └─ stcp 隧道（经你的 frps 中转，只有同 sk 的 visitor 能接）
            └─ 电脑上的 frpc（type = stcp 的 proxy）
                 └─ 电脑局域网地址:3443（DSH Mobile 的 HTTPS 网关）
```

实际变化只有两处：网关的服务器证书 SAN 增加 `127.0.0.1` 与 `::1`，并额外接受 `https://127.0.0.1:<隧道端口>` 与 `https://[::1]:<隧道端口>` 两个精确 Origin。除此之外没有变化。

## 必读：两端端口必须一致

> **端口怎么定**：默认情况下，手机端 visitor 的 `bindPort` 要填**电脑端 DSH Mobile 网关的监听端口**（默认 `3443`），电脑端 frpc 的 `localPort` 填同一个端口。如果你希望 visitor 用别的端口（例如 `6000`），在面板的「隧道端口」里填该端口并点「应用端口」——网关会按这个端口接受回环 Origin，无需改动网关自身的监听端口，也不必先关再开那个开关。两端 `bindPort` 与 `localPort` 始终要一致。
>
> 网关按**精确的** `Host`/`Origin` 接受请求：默认就是 `127.0.0.1:<监听端口>` 与 `[::1]:<监听端口>`；填了「隧道端口」后，则按该端口接受。所以两端的 `bindPort` / `localPort` 必须彼此相同，并且与面板里的设置一致——对不上时隧道可能显示已建立，但网关会返回 403。这是刻意的限制：只接受你显式声明的那个回环端口，不会变成接受任意端口的通配入口。

## 前提

- 电脑端「移动访问 → 局域网」由 DSH Mobile 管理并已完成配置。这个开关只对这类配置可用；读取不到或不支持的配置无法保存，面板会显示「仅托管局域网配置支持此设置」。
- 你自己的 frps 已运行，手机与电脑都能连到它的控制端口。
- 建议 frp 0.52.0 或以上并用 TOML 写配置；旧版 INI 仍可运行但已被上游弃用。
- 手机安装了 Termux（或能运行 frpc 的环境），本地 `3443` 端口未被占用。
- 这条链路不需要给电脑开放任何入站端口；只有你 VPS 上的 frps 控制端口需要可达。

## 电脑端：frps 与 stcp proxy

frps 侧只需要一个正常的 stcp 服务端，不必为这个代理写额外规则，`frps.toml` 示例：

```toml
bindPort = 7000
auth.method = "token"
auth.token = "替换为高强度令牌"
```

电脑上的 `frpc.toml`（stcp 的 server 侧，与 DSH 在同一台电脑）：

```toml
serverAddr = "你的 VPS 地址"
serverPort = 7000
auth.method = "token"
auth.token = "替换为高强度令牌"

[[proxies]]
name = "dsh-mobile-gateway"
type = "stcp"
secretKey = "替换为足够长的随机 sk"
localIP = "192.168.1.20"
localPort = 3443
```

- `localIP` 填**这台电脑上网关实际监听的局域网地址**（例如面板「局域网」里显示的 `192.168.1.20`）。网关绑定在局域网地址上，来源网段检查也只接受该局域网网段（以及你另外添加的可信网段），所以**不要填 `127.0.0.1`**。
- `localPort` 填网关监听端口（默认 `3443`）。
- `secretKey` 是 stcp 的 `sk`，两端必须一致；不要复用 frps 的 token。
- 启动前可用 `frpc verify -c frpc.toml` 检查配置。

## 手机端：Termux 里的 visitor

下载与手机架构匹配的 frp（版本号和文件名以 [frp releases](https://github.com/fatedier/frp/releases) 页为准，下面只是示例；arm64 手机一般用 `linux_arm64`，32 位设备用 `linux_arm`）：

```sh
pkg install wget tar openssl-tool
wget https://github.com/fatedier/frp/releases/download/v0.72.0/frp_0.72.0_linux_arm64.tar.gz
tar -xzf frp_0.72.0_linux_arm64.tar.gz
```

手机上的 `frpc.toml`：

```toml
serverAddr = "你的 VPS 地址"
serverPort = 7000
auth.method = "token"
auth.token = "替换为高强度令牌"

[[visitors]]
name = "dsh-mobile-visitor"
type = "stcp"
serverName = "dsh-mobile-gateway"
secretKey = "与电脑端完全一致的 sk"
bindAddr = "127.0.0.1"
bindPort = 3443
```

- `serverName` 必须等于电脑端 `[[proxies]]` 的 `name`。
- `bindAddr = "127.0.0.1"` 只在手机本机回环监听，不会让同一 Wi-Fi 的其他设备接入。
- `bindPort` 与电脑端 `localPort` 必须相同；默认就用网关的监听端口。要用别的端口时，在面板「隧道端口」里填同一个值。

运行 visitor：

```sh
cd frp_0.72.0_linux_arm64
./frpc -c ./frpc.toml
```

Termux 可能被系统回收，需要你自己保持它在前台或加锁运行；插件不管理这个进程。

如果仍在使用旧版 INI 配置，等价的访问端写法如下（`role = visitor` 属于旧语法，新版建议改用上面的 TOML）：

```ini
[common]
server_addr = 你的 VPS 地址
server_port = 7000
token = 替换为高强度令牌

[dsh-mobile-visitor]
role = visitor
type = stcp
server_name = dsh-mobile-gateway
secret_key = 与电脑端完全一致的 sk
bind_addr = 127.0.0.1
bind_port = 3443
```

## 电脑端：开启开关并生成回环配对链接

1. 打开 **移动访问 → 局域网**，展开 **回环隧道接入 · 高级** 折叠块，点击显示「已关闭」的开关，使其变为「已开启」（插件 0.8.12 起提供；仅托管局域网配置可用）。
2. 开关保存后状态会提示需要重启：关闭再重新开启局域网访问，或重启 DSH。网关重新绑定局域网时会重新签发服务器证书，SAN 中同时包含原局域网地址、`127.0.0.1` 和 `::1`；局域网地址仍是主地址。
3. 再次点击 **生成配对二维码** 或 **复制配对链接**。开关开启时，配对操作成功后操作行里会多出一个 **复制回环配对链接** 按钮，复制到的就是回环地址的链接，形如 `https://127.0.0.1:3443/mobile-access/pair#instance=…&token=…`。它与局域网链接共用同一个一次性配对码；二维码仍按局域网地址生成。按钮只在网关确实返回了回环链接时出现，没有出现说明开关尚未重启生效。
4. 在手机 App 的 **局域网访问** 流程里粘贴这条回环链接。面板不生成回环地址的二维码——二维码只编码局域网地址，在这里用不了，因为手机不在那个局域网里。手机不在这台电脑的局域网里，自动发现也不会列出它，直接用链接即可；App 会把回环地址当作局域网入口处理。也可以直接在手机浏览器打开这条链接。
5. 用浏览器访问时首次会提示私有证书不受信任，这是自签 CA 的正常现象；确认链接来自自己的电脑后再继续。App 会从网关读取 CA，并核对配对码中 `instance` 所代表的 CA 指纹。

在手机 Termux 里可以先确认隧道是否通到网关：

```sh
curl -fsS -k https://127.0.0.1:3443/mobile-access/health
# 期望输出 {"ok":true}；-k 只用于跳过证书校验，不能证明入口身份
```

再确认证书里已经有回环地址：

```sh
openssl s_client -connect 127.0.0.1:3443 </dev/null 2>/dev/null | openssl x509 -noout -text | grep -A1 'Subject Alternative Name'
# 应能看到 IP Address:127.0.0.1（IPv6 可能显示为展开形式）
```

## 关闭与拆除

1. 展开 **回环隧道接入 · 高级**，把显示「已开启」的开关切回「已关闭」，同样需要重新绑定局域网（关闭再开启局域网访问，或重启 DSH）才生效。生效后网关不再接受回环 Origin，证书重签后不含回环地址，也不会再生成回环配对链接。
2. 停掉手机上的 frpc visitor 和电脑上的 frpc，删除 frps 上对应的 stcp 配置，这条链路即完全拆除。
3. 插件不安装、不配置也不管理 frp，frps/frpc 的进程、配置文件和 VPS 侧规则都需要你自己清理。
4. 关闭开关不会删除已配对设备；只想临时使用时，建议用完后停掉手机端 visitor。

## 残余风险（请自行评估）

1. **手机回环端口对同设备所有 App 可见**：手机上的 frpc visitor 一旦监听 `127.0.0.1:3443`，同一台手机上的任何应用都能连到它，Android 没有「只允许某个 App 访问回环端口」的隔离。登录仍需要 DSH Mobile 的配对凭据，但不要把它当成操作系统级隔离。
2. **先占端口可以冒充网关**：如果手机上已有别的应用抢先占了 `127.0.0.1:3443`，它会先接到连接。App 会因为你配对的 CA 指纹对不上而拒绝，但如果你在浏览器里点过「继续访问不受信任的证书」，那条一次性配对令牌就可能被截获。所以不要在浏览器里忽略证书警告，并且只在确认该端口属于你自己的 frpc 时才继续。
3. **证书多了一个回环 SAN**：开启后服务器证书的 SAN 增加 `127.0.0.1` 与 `::1`（原局域网地址仍保留）。这不影响 App 按设备固定 CA，伪造证书仍然需要你的 CA 私钥；代价只是证书里多出现两个回环名字，它本身不能让别人访问到你的网关。
4. **只多允许了几个名字**：该开关没有放宽 Origin/CSRF 检查、来源网段、配对凭据或其他校验。请求仍必须来自允许的网段、Host 与 Origin 必须精确匹配、仍需有效配对。它不建立 VPN、不改防火墙、不发布任何公网端口。
5. **你自己的链路强度决定整体安全**：frps 的 token、stcp 的 `sk`、frps 控制端口的暴露面都由你配置，插件既不读取也不校验，也不会在它们出错时替你兜底。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 隧道显示已建立，但页面返回 403 `forbidden` | 手机端 `bindPort`、电脑端 `localPort` 与面板「隧道端口」三者不一致，Host 不是已声明的回环 authority。把三处改成同一个值 |
| 返回 403 `source_network_untrusted` | 电脑端 frpc 的 `localIP` 指向了不在允许网段的地址（例如 `127.0.0.1`）。改成网关实际监听的局域网地址 |
| 访问 `https://127.0.0.1:3443` 证书报错 | 开关未重启生效，或者证书尚未重签。重新绑定局域网后再试；不要在浏览器或 App 里关闭证书校验 |
| `curl` 连不上 `127.0.0.1:<端口>` | 手机端 frpc 未运行、`serverName`/`sk`/token 不一致，或 frps 控制端口不可达 |
| App 的局域网发现列表里没有这台电脑 | 该入口不走局域网广播发现；用 **复制回环配对链接** 得到的链接配对。二维码只编码局域网地址，在这里不适用 |
| 手机提示端口被占用 | 手机上已有程序占了该端口。可以在面板「隧道端口」里换一个空闲端口，并把两端 frpc 的 `bindPort` / `localPort` 改成同一个值；不必释放原端口 |

## 与其他通道的关系

- **接入既有 frps**（[指南](ATTACH_EXISTING_FRPS.md)）由插件管理本机 frpc，并在 frps 上发布公网 HTTPS 入口，手机直接访问公网地址；本文相反：frpc 由你自己管理，不发布任何公网入口，手机访问的是自己的回环地址。
- **iroh** 由插件管理通道，不需要公网服务器；stcp 需要你的 frps，但通道完全由你控制。
- **自有反向代理 / 托管 Caddy** 需要你已有公开 HTTPS 入口，与本页的组合方式不同。

frp 配置语法以官方文档为准：[stcp 示例](https://gofrp.org/zh-cn/docs/examples/stcp/)。
