# 连接诊断与测量范围

[English](CONNECTION_DIAGNOSTICS.en.md) · [返回文档](README.md)

> 分层报告自插件 0.8.2 起提供；0.8.1 的诊断字段与提示较少。这项电脑侧功能不要求更新 App。

电脑端打开 **移动访问 → 诊断**，点击开始检查。诊断只读取配置、组件状态和有限的网络结果，不发送模型请求、不修改 DNS、代理、防火墙或配对。运行中的检查会禁用重复操作；报告生成后可复制脱敏结果。

## 怎样读结论

诊断卡片和复制报告都标明范围：**配置信息、电脑侧检查、手机尚未验证**。绿色只表示对应的本机项目得到成功结果，不表示手机已能完整使用 DSH；错误也只描述被测路径，不能直接推断所有网络都不可达。

| 层次 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 版本信息 | 正在运行的插件、DSH 及声明的最低 App 版本 | 不能代替兼容矩阵或真机验证 |
| 网卡与网关 | 电脑使用的接口、监听状态 | 不能证明手机路由、热点隔离或跨网段访问正常 |
| Windows 防火墙 | 是否找到所需的启用规则 | 不能覆盖全部安全软件、策略或交换机限制 |
| 本机通道状态 | 提供方报告组件就绪、连接中、等待登录或失败 | `ready` 不代表公网、手机或页面资源已验收 |
| 系统 DNS | 电脑解析到的地址类别及 IPv4/IPv6；不复制具体地址 | DNS 有结果不等于端口可达；等待超时只表示本次未取得上下文 |
| 电脑出口探测 | 当前出口的 HTTP 结果，或 DNS、连接、TLS、等待、HTTP 阶段失败 | 仅检查健康路径的 HTTP 状态，不验证健康正文、登录、脚本执行或会话投递 |
| 手机路径 | 明确列出仍需在手机上验证的部分 | 电脑不会代替手机完成配对页面、资源与 WebSocket 验收 |

代理兜底成功会单独标注为电脑的代理出口，不会覆盖系统 DNS 的私网分类，也不表示手机使用了相同代理。未开启的 LAN 配置和防火墙项目不应被当作远程入口故障。

页面脚本检查使用当前已认证请求的公开 Peer 接口，不伪造身份。某个可选脚本观测失败时会明确显示未完成，不会把它当作“没有其他远程插件”，也不会隐藏其他网络检查结果；认证被拒绝时仍拒绝读取报告。

## 同一 tailnet 下的 Funnel

内置 Funnel 组件使用 `tsnet.FunnelOnly()`：它只接收公网 Funnel 入口的连接，不接收 tailnet 内部直连。如果 MagicDNS 把这个名称解析到节点的 `100.64.0.0/10` 或 Tailscale IPv6 地址，电脑会走私网路径；该路径失败不代表公网 Funnel 也失败。普通官方 Funnel 配置不一定具有这个限制。参见 [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel) 和 [MagicDNS](https://tailscale.com/docs/features/magicdns)。

这类结果显示为需对照确认，而不是把公网标成故障或正常。它**不会修复手机访问私网路径本身**：应先用 tailnet 外的网络验证，例如在条件允许时使用另一条网络。是否临时调整某台设备的 Tailscale DNS，由使用者自行决定；它可能影响其他私网服务，测试后应恢复。不要自动关闭整个 tailnet 的 MagicDNS。

`100.64.0.0/10` 不是 Fake-IP。诊断把它与 `198.18.0.0/15` 的常见 Fake-IP 网段分开；混合解析结果也不会仅凭其中一个私网地址就认定是 MagicDNS 遮蔽。即使解析到 tailnet 地址，真实 TLS 身份错误或 HTTP 拒绝仍保留为对应失败，不会被降级提示掩盖。

## 按失败阶段排查

- **DNS**：检查当前系统解析和网络策略，先与另一条网络对照，不默认改用公共 DoH。
- **连接**：核对当前路由、端口和入口；不把 TCP 拒绝自动归因为代理、证书或配对。
- **TLS**：核对证书、主机名和代理路径。不要关闭证书或主机名验证。
- **等待超时**：只说明探测预算内没有完成，不能定位具体故障节点。
- **HTTP**：检查健康路径是否被服务商策略或反向代理路由拦截。探测不会发送配对凭据。
- **未知**：当前证据不足以细分，不把原始异常、URL 或响应内容写入报告来猜原因。

会话可用但定制失败，应另外检查清单、CSS、脚本和更新流。`http failure` 的传输错误、解析错误与上游拒绝也不能混在一起；见[慢链路诊断](SLOW_CONNECTIONS.md)。iroh 和自有反向代理的本机就绪信息，不是公网验证；见 [iroh](IROH.md) 与[自有反向代理](SELF_HOSTED_ORIGIN.md)。

## macOS：打开工作区目录时超时

macOS 可能在电脑上要求 DSH 授权访问「桌面」「文稿」「下载」等受保护的位置。如果远程超时恰好发生在打开目录时，先回到 Mac 检查是否有待确认的系统提示；超时本身不能证明配对失效，也不能单凭它断定是权限问题。

无人值守前，在 Mac 上用实际启动方式运行 DSH，并打开远程会用到的工作区目录。若弹出提示，只在确有需要时授权；已有目录权限可在「系统设置 → 隐私与安全性 → 文件与文件夹」检查。也可将新的工作区放在不需要此类授权的目录。处理提示后，先用原有配对重试。远程访问不以开启「完全磁盘访问」为前提。参见 [Apple 的文件与文件夹权限指南](https://support.apple.com/zh-cn/guide/mac-help/mchld5a35146/mac)。

离开前，用已配对设备走计划使用的远程通道，在网页目录选择器里进入**同一个目录**并确认能列出内容。只检查网关健康或在终端运行 `ls`，不能验证 DSH 有权访问该目录。如果 Mac 弹出提示，处理后用原有配对重试；不用重置系统权限或重装插件。

远程通道就绪后，移动访问面板也可能提示开启「完全磁盘访问」。这是为无人值守访问减少受保护目录授权弹窗的建议，不会阻断配对或远程连接；按钮只打开系统设置，不会由插件修改权限。

## 分享报告

报告保留版本、接口名称、脱敏端点后缀、失败阶段、耗时、系统 DNS 类别和测量范围。不读取会话正文，不包含配对密钥、Token、Cookie、完整域名、完整 IP 或代理凭据。接口名称等上下文仍可能具有辨识性，公开前应再检查一遍。

建议补充实际手机网络、失败时间，以及停在配对、页面、资源还是会话连接阶段。不要上传原始配对二维码或描述符；报告中的“未验证”不是“验证失败”。
